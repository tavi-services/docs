title: "Quickstart"
description: "File your first work order and read it back."
---

You need an API key and the API base URL. Your Tavi team gives you both, starting with a sandbox key whose work orders never reach a real provider.

In the examples, `$TAVI_API` is the base URL and `$TAVI_KEY` is your key.

## 1. List your sites

```bash
curl "$TAVI_API/api/v1/locations/" \
  -H "X-Tavi-API-Key: $TAVI_KEY"
```

```json
{
  "items": [

      "id": "6f1c2a8e-3b7d-4c55-9a51-0f2a1e9c7b10",

```

No site yet? [Create one](/sites).

## 2. File a work order

```bash
curl -X POST "$TAVI_API/api/v1/jobs/client/" \
  -H "X-Tavi-API-Key: $TAVI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "location_id": "6f1c2a8e-3b7d-4c55-9a51-0f2a1e9c7b10",
    "trade": "PLUMBING",
    "description": "Toilet in the back-of-house restroom is clogged and overflowing.",
    "deadline_date": "2026-11-16",
    "price_dne_requirement": 750,
    "site_contact": {
      "first_name": "Dana",
      "last_name": "Lee",
      "phone": "+15125550142"
    },
    "escalation_contact": {
      "first_name": "Pat",
      "last_name": "Kim",
      "title": "Facility manager",
      "phone": "+15125550199"
    },
    "context": "Back door code 4412. Open 7am-10pm."
  }'
```

The response is the new work order, with `job_status` set to `DRAFT`. Keep its `id`.

## 3. Read it back

```bash
curl "$TAVI_API/api/v1/jobs/client/$JOB_ID" \
  -H "X-Tavi-API-Key: $TAVI_KEY"
```

Read it again whenever you want to show progress. See [tracking work orders](/tracking) for what each field means, and [example work orders](/examples) for what a work order looks like at each stage.
